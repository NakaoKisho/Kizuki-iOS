# 委譲と成果物の受け渡し

親は `.codex/agents/*.toml` のdescriptionと専門性を読み、目的に合う担当を選ぶ。役割名に工程を固定しない。モデル・effortは定義に固定しない。

独立レビューは担当箇所の作者とは別コンテキストで行う。並行編集はファイルの所有範囲を分ける。

## 委譲する内容

親は目的、task、phase、参照資料、編集可能範囲、受け入れ条件、対象ファイル群と出力先を指定する。未決定の判断を暗黙に委ねない。レビュー担当も報告ファイルを書けるようにし、レビュー対象の編集は許可しない。

作業開始前に[出力契約](output-contract/contract.md)のprepareを実行する。各担当は指定runへ報告を保存し、最終メッセージにREPORT_PATHを付ける。設計・実装・レビュー以外の調査でも同じ契約を使う。

## 次工程へ進む条件

親は今回のrunに対してcheckを実行し、全参加者の報告・対象版・結果が有効であることを確認する。非0なら次工程へ進めず、修正または未完了を報告する。checkの成功は内容の正しさの認定ではなく、根拠と受け入れ条件の確認も必要である。

新しい実行や再レビューはprepareで別runを作る。前の報告をコピーして再利用しない。対象が変更された報告は失効するため、影響範囲を確認したうえで新しい対象版を報告する。

## Hookの有効化

Codexのプロジェクトhookは、クライアントの`/hooks`等で定義を確認し信頼する。現在のセッションに追加ファイルが自動反映されたと仮定しない。SubagentStopは専門エージェントの報告形式を確認する。hookが未有効・未対応でも、親のcheckを省略しない。

未出力・不正出力は差し戻す。差し戻し後も不正なら継続を止めるが、合格にはしない。次工程の入口では引き続きcheckが必要である。
